# Troubleshooting Guide: Common gRPC & Node.js Issues

## 1. `14 UNAVAILABLE: No connection established`
- **Cause**: The client attempted to connect before the server was bound, or the server is running on a different port/host.
- **Solution**:
  - Verify the server is running with `netstat -ano | findstr <port>` (Windows) or `lsof -i :<port>` (Linux/macOS).
  - Ensure the client connects to `127.0.0.1:<port>` rather than `localhost` if IPv6 resolution is inconsistent.

---

## 2. `4 DEADLINE_EXCEEDED: Deadline exceeded`
- **Cause**: The RPC took longer to complete than the deadline specified by the client.
- **Solution**:
  - Check whether the server handler performs slow blocking operations without responding.
  - Increase the deadline parameter in `deadline: Date.now() + ms`.
  - Check whether downstream services called by the server have stalled.

---

## 3. `12 UNIMPLEMENTED: Method not found`
- **Cause**: The requested method does not exist in the server implementation or has a case-sensitivity mismatch.
- **Solution**:
  - Verify that the method name in the server implementation matches the camelCase method name generated by `@grpc/proto-loader` (e.g., `SayHello` in `.proto` maps to `sayHello` in JavaScript).
  - Check that the client is calling the exact package and service name specified in the `.proto`.

---

## 4. `3 INVALID_ARGUMENT: Cannot find field...`
- **Cause**: Passing incorrect fields or types that violate the Protocol Buffer schema.
- **Solution**:
  - When `keepCase: true` is configured, field names in JavaScript objects must match the exact snake_case names in the `.proto` file (e.g., `user_id` instead of `userId`).

---

## 5. TLS Handshake Failures / `UNAVAILABLE: Handshake failed`
- **Cause**: Hostname verification failure or self-signed certificate rejection.
- **Solution**:
  - Ensure the client passes the CA certificate when constructing credentials:
    ```javascript
    grpc.credentials.createSsl(caCert);
    ```
  - Ensure the certificate Common Name (CN) or Subject Alternative Name (SAN) includes the address used by the client (e.g., `localhost` or `127.0.0.1`).

---

## 6. Jest Hangs or Does Not Exit After Tests
- **Cause**: Active gRPC HTTP/2 server sockets or client channels keep the Node.js event loop active.
- **Solution**:
  - Always call `client.close()` and `await new Promise((r) => server.tryShutdown(r))` in teardown blocks.
  - Run Jest with `--runInBand --forceExit` as configured in `npm test`.

---

## 7. `grpcurl` Connection Errors
- **Cause**: `grpcurl` requires server reflection to discover methods without passing explicit `-proto` files.
- **Solution**:
  - Register `@grpc/reflection` on the server:
    ```javascript
    const { ReflectionService } = require('@grpc/reflection');
    new ReflectionService(packageDefinition).addToServer(server);
    ```
  - Use `-plaintext` for insecure local servers:
    ```bash
    grpcurl -plaintext 127.0.0.1:50051 list
    ```
